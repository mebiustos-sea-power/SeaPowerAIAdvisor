## 2. 採用した設計判断

### 人物・参加状態・発言資格

- 就任は参加チェックと無関係に、現在の取得範囲にいる未就任の全ユニットを対象とする。編隊員も含むが、発言資格は現在の編隊構成から別に判断する。
- 新しい人物の就任成功時は参加ON。既存人物の交代・編集では参加ON/OFFを維持する。未就任と、就任済みの参加OFFを混同しない。
- 追加ユニットの自動就任は初期OFF。最初の人物が確定してから、Chatterの設定周期で未就任者をまとめて確認する。ON以前からの未就任者も含み、確認だけで対象がいなければ通信しない。
- 全員が参加OFFでも、自動就任の確認は続ける。新規就任で交信が再開し得るため、処理全体を止める操作はChatterの一時停止・機能無効化と分ける。
- ゲーム一時停止中は自動確認と発言周期を止め、再生倍率には追従しない。明示した就任要求はゲーム一時停止中にも実行できる。自動就任OFFは自動要求だけを取り消し、手動要求や既存人物を維持する。

### 登録キャラクターと配属

- 顔画像、名前、性別、国籍、性格、階級を任意に登録する。画像だけ、または全項目未設定の登録も1件のキャラクターとして扱う。画像を共有することと、同じ人物の重複就任は別の概念。
- 性別は未指定・男性・女性、国籍は自由入力。指定済みの性別・国籍は人物自身の確定情報であり、名前などの補完にも使う。就任先ユニットの所属国と混同しない。
- 名前・階級・性格の指定済みの値はMODが保持し、AIによる翻訳・短縮で置き換えない。性格は255文字までの自由記述とし、話し方なども記載できる。未設定部分だけをAIが補完し、登録元へ自動で書き戻さない。
- 「AIによる就任」は対象外・通常・優先の3段階。対象外でも手動指定はでき、優先でも採用を保証しない。
- 「就任先」は無指定・船舶・航空機。船舶には潜水艦、航空機にはヘリコプターを含める。軍種の指定ではなく、自動選定時の候補条件としてMODが扱う。手動指定は制限しない。
- 配属の自然さはAIが判断する。人物自身の国籍・階級と、ユニットの所属・役割・任務背景に整合性があることを目指し、国別の対応表や国籍一致の一律判定をMODに追加しない。
- 「重複就任を許可」は初期OFF。現在の就任・就任待ちに基づき新規割り当てを制限する。OFFへの変更で既存の配属や受付済み要求を解除しない。同じユニットへの再就任、交代や対象消失後の再利用は許容する。過去履歴だけでは登録を使用中と数えない。
- 登録の編集・削除は、就任済み人物・過去履歴・生成待ちの登録内容を変更しない。就任済み人物は登録IDを保持できるが、表示する名前などは確定値として独立させる。

### 就任生成の段階分け

登録候補を使う自動就任は「配属適合性の評価 → 配属・階級 → 名前・性格」の3段階。登録候補のない新規生成と、手動指定人物の補完は評価を省いた2段階。名前・階級・性格が揃った登録人物の手動就任はAI通信を行わない。個別の「AIで再就任」は登録候補を選び直す操作ではなく、新しい人物を生成する。

一括応答では人物の国籍と名前などの不整合が残ったため、頻度の低い就任処理では通信増より整合性を優先した。名前を補完する段階へ就任先の国籍やブリーフィングを混在させず、決まった個人情報を渡す。配属評価の説明を人物状態や通常交信へ再送しない。

生成完了前に一部の就任結果を反映せず、失敗・キャンセル時は既存人物と参加状態を維持する。通常交信は就任から独立した1通信のまま。成功・失敗にかかわらず、実際の各API要求を使用量へ計上する。生成される階級の表記は回答言語に従う。

### 編集・再就任と画面の役割

- 参加ユニット一覧へ「編集」「AIで再就任」「登録から就任」を置く。人物の編集と、人物そのものの交代は別の操作とする。
- 就任済み人物の名前・階級・性格・画像を、AI通信なしで編集する。生成中の古い発言や未表示通知を、新しい人物へ付け替えない。過去履歴は当時の人物を保持する。
- ライブラリは登録キャラクターと顔画像を管理する。キャラクター一覧から直接編集へ進み、保存成功後は一覧へ戻る。顔画像の選択はワンクリックで編集下書きへ反映する。
- 画像のライブラリ追加・置き換えはプレビュー後に確定する。人物・登録キャラクターの保存や取消しとは独立した操作とする。
- 登録キャラクターから反映項目を選ぶ機能は採用しない。画像は画像ライブラリから選び、その他の部分変更は通常の人物編集を使う。

### 顔画像の所有と寿命

顔画像ライブラリが永続ファイルを所有し、登録キャラクター、就任中の人物、セーブは画像IDを参照する。登録キャラクターIDは人物の出自・重複管理、画像IDは表示画像の参照に使い、画像だけ変えても人物の登録元を切り替えない。

- 人物の交代や画像の選び直しではファイルを複製・削除しない。画像の削除はライブラリで明示的に行う。全セーブの参照追跡や、未使用画像の自動回収は行わない。
- 画像の置き換えは同じ画像IDの内容更新とし、共有する表示にも反映する。昔のセーブと同じ画素を厳密に再現する保証は設けない。画像がなければ共通アイコンを使い、不正・読み込み不能な画像はエラーとして示す。
- 画像本体をAIや戦闘セーブへ送らない。外見に合わせた性別・国籍などは、必要ならユーザーが登録する。
- PNG・JPEGを受け付け、入力時の8MiB・各辺4096pxの保護を維持する。取り込み時に長辺256pxまで縦横比を保って縮小し、元ファイルを変更しない。切り抜き・拡大はしない。
- ファイルの永続保持と描画キャッシュの寿命は分ける。ライブラリ全画像の常時デコードを前提にしない。

人物用コピーを編集時に削除する旧方式や、履歴から画像参照を追跡して回収する案は、この所有分離で置き換えた。

### 保存・ロード

- ユニットと人物の対応、確定した人物情報、登録ID・画像ID、参加ON/OFF、Chatterの停止状態、階級の共通表示順と累積票を保存する。対応付けにはゲーム本体の保存用固有IDを使い、地図上の番号変更で別人へ配属しない。
- 登録台帳・画像ライブラリ・API接続・生成周期などは戦闘セーブへ複製しない。画像や登録元がなくても、保存された人物の確定情報を維持する。
- 過去の交信、重複回避用の直近発言、通知、生成途中・就任待ちの要求、残り時間、使用量は保存しない。再就任途中なら旧人物を保存し、要求を自動再送しない。
- ロード後の初回は設定周期を待たず、ゲーム一時停止の解除後に生成機会を設ける。沈黙でも生成完了として扱い、その後は生成完了から設定周期を待つ。Chatter自体が停止中なら明示的な再開まで通信しない。
- Crewが形式と復元を所有し、MOD本体が他機能の保存情報と束ねる。SharedへCrewの設定・人物形式を持ち込まない。MOD共通の保存ON/OFF・互換性管理を使い、Crew無効時の復元待ちデータも再保存できるようにする。
- Crew情報のない既存セーブは未就任から始める。未リリースの途中形式を救済する移行は追加しない。

### 標準サンプル

現在の4人（米国籍、男女それぞれ船舶用・航空機用）と顔画像を同梱する。名前・階級・性格は未設定のまま、就任時のAI補完を使う。

キャラクター登録ファイルがまだない場合だけ取り込む。既存ファイルが空でもユーザーの選択として維持し、編集や削除をアップデートで上書きしない。画像を先に取り込み、4人の登録を最後にまとめて保存して、中断後も再試行できるようにする。既存ファイルの異常を初期状態として隠さない。

将来サンプルを追加・変更しても既存利用者へ自動反映しない。再取り込みUIや外部パックの読み込みは、今回の初期化処理に含めない。

## 4. 後続で決めること

- 外部キャラクターパックの形式と探索方法。DLLを不要にし、設定ファイルと画像だけで追加できる方向は構想として維持する。
- 外部パックの識別ID、重複時の上書き規則、複数パックの優先順位。ユーザー登録の名前変更と独立したIDは実装済みだが、パックの具体的なID規則を確定した扱いにしない。
- パック由来の人物・画像の所有、更新・削除、ローカル登録との表示・管理の関係。他MODが所有するファイルを、ローカル画像の削除操作で消さない。
- 現在の取得範囲を超えて、未発進の搭載機などへ就任対象を拡張する必要があるか。今回は取得範囲を広げていない。

自動生成した人物を登録へ保存する逆方向の機能などは追加候補であり、今回の完了条件へ加えない。残作業を別ブランチへ分ける場合も、必要な採用理由と検討事項を引き継ぐ。
