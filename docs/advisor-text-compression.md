# ミッション文章のAI向け圧縮

2026年11月1日。現在の設計意図と判断理由を記録する。細かな形式・条件はコードを参照する。

## 目的と範囲

ブリーフィングと公開情報報告を繰り返し利用するときの入力トークンを減らす。通常の相談と同じ応答で圧縮情報を受け取り、専用の生成要求は増やさない。初回には出力と処理時間が増えるので、初回の負担と再利用後の効果を分けて評価する。

会話履歴、操作履歴、戦況の数値データ、キャンペーン、Crewは対象外。少ない件数の会話履歴まで圧縮すると、毎相談の生成負担と文脈管理が増えるため、初期範囲から除外した。

## 採用した方針

- 圧縮情報はAIが読む英語の情報とし、人向けの文章である必要はない。重要な対象・目的・制約・期限・数値・単位・否定・不確実性を保持する。ユーザーへの回答は従来の回答言語を使う。日英の要約比較試験は行わない。
- 情報の提供可否と送信タイミングは、既存の情報選択と接続の送信方式に従う。圧縮のためだけに未要求の原文を送り出さない。
- `summary_required` は、受け取った情報について圧縮情報の返却が必要かを表す。機能OFFでは原文を使い、この値もfalseにする。「原文を要約済みと偽る」フラグにはしない。
- 返却は最終応答にまとめる。回答と補助情報を一緒に受け取って相談を完了でき、途中で圧縮情報だけを提出させるための続行処理を増やさずに済むため。圧縮情報は会話画面へ出さない。
- ブリーフィング全体・報告1件をそれぞれ単位とし、同じ戦闘のメモリ内で再利用する。原文との対応を確認し、対象外になった情報は保持し続けない。ロードで破棄し、ファイルには保存しない。
- 報告の取得用IDは直近一覧の入れ替わりで変わるため、そのIDだけで原文を対応付けない。原文と報告時刻に基づいて対応させる。別の戦闘や更新前の原文に、遅れて返った圧縮情報を適用しない。
- AIが原文を取り直す専用の経路は設けない。表示されるゲーム側のブリーフィングは変更しない。
- 補助情報の不正・欠落は診断に残して保存せず、正常な回答は受理する。自動的な追加生成はしない。回答自体の不正や通常の通信障害は既存のエラー処理に従う。
- 設定は「AIに渡す情報」の「ブリーフィング・情報報告の要約を利用する」。初期OFFとし、リリース前に正式な初期値を決める。進行中の相談には開始時の設定を使う。

## 責務

戦闘連携が保持期間を所有し、原文の取得・情報権限は既存の戦況取得が担当する。圧縮セッションは送った原文と返却内容の対応・受理を担当し、標準相談エンジンが最終応答を処理する。通信アダプターへミッション情報や要約の意味を持ち込まない。独自の相談処理を持つ拡張には標準エンジンの返却形式を強制せず、従来の原文を提供する。

保持済みの対象だけで済む相談には、圧縮返却用のツール・指示を追加しない。元の問い合わせ結果は、その相談の切り離された情報として扱う。同じ相談内の既存通信履歴の差し替えは今回行わず、次の相談での再利用を主な削減対象とする。

## 初期の実通信確認

B6・DeepSeek V4.1 Flash 1017で、原文と圧縮情報の再利用を比較した。先行送信・履歴なしでは入力が27,197から26,855トークンへ減少した（342、全体の約1.3%）。初回の入力は返却用ツールと指示で461トークン増え、さらに圧縮情報の出力も必要になる。回答自体の長さにも変動があるため、総トークン数から回収回数を断定しない。

3つの送信方式で相談が完了し、移動案2件の承認待ちと初回圧縮情報の返却も同じ相談で両立した。圧縮だけの追加要求は設けていない。B6には公開情報報告がないため、報告の再利用・入れ替わり・不正な返却の扱いは自動検証の範囲である。

短い別候補の指示も試したが、明確な改善を確認できず採用しなかった。圧縮には通常の回答と同じく、AIが不確実性を弱めるなどの情報損失が残り得る。初期OFFを維持し、より長い文章や異なるモデルでも常に有利とはみなさない。
